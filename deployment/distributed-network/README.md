# Reviewed distributed networking

Install source support only: `ansible-playbook -i inventory install.yml -e distributed_network_install=true`. Inventory group `distributed_network_hosts` must contain intended hypervisors only. No profiles, links, routes or addresses are changed by this playbook. Preserve any site broker differences when merging source; deploying a whole broker requires the matching source bundle. Installer `hypervisor/install-product.sh` includes the module for future builds.

Manager Networking → Distributed switches: select enrolled hosts. Read-only discovery lists physical interfaces, bridges, bridge membership, active state and MTU for each host. A sole common eligible unused uplink pre-populates the form. Different or protected host configurations stay visible and read-only. Existing unmanaged bridges are never silently adopted; existing Manager-owned switches populate edit forms. New bridges require a unique Linux name, common unused physical NIC, MTU 1280–9000 and unique named VLAN port groups (0 untagged, 1–4094 tagged).

Review collects each host's current state fingerprint. Confirm applies sequentially only to selected hosts, stops on the first failure and stores individual results. Discovery and review make no network changes. No automatic retry is implemented. A new review is required after any observed state change. Management/addressed/routed links, other bridge/bond members, existing profiles and libvirt references including powered-off guests block changes. This first implementation also requires managed bridges to be unused for updates/deletes; live migration is out of scope.

The parent bridge carries the trunk uplink without IP configuration. Untagged groups map to that bridge. Each tagged group gets a deterministic VLAN interface and access bridge (`vp…`) for VM attachment; host results include exact mapping. Physical switch trunk/VLAN allowance must already exist; this workflow cannot configure upstream hardware. It uses persistent NetworkManager profiles and restores original uplink MTU on delete. It does not change management addressing, hostnames, DNS or routes.

Apply journals state before mutation and removes newly created profiles on failure; updates restore the prior owned specification when possible. Failed rollback or interrupted apply remains blocked pending operator reconciliation. NetworkManager/host crashes cannot be made globally atomic; the Manager records partial results. No unowned profile is removed. Never automatically replay an ambiguous apply.

Deployment verification: run Python tests, Go handlers/routes tests, frontend type-check; deploy matching module/broker and Manager build; invoke discovery and preview. Real create/update/delete validation requires a spare unconfigured physical NIC on every selected host and an explicit reviewed apply. No live network mutation has been performed as part of this source change.
